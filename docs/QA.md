# 五轮自检报告

检查日期：2026-11-16（Asia/Shanghai）。环境：Windows、Node 22.14.0、Microsoft Edge/Chromium 自动化。项目包含可重复运行的测试脚本，以下区分真实交互、构造条件测试与未验证的范围。

## 第 1 轮 · 可运行性

**检查点**：完整文件、模块入口、依赖安装、生产打包、标题页、首个可玩画面、控制台异常、依赖漏洞。

**发现的问题 → 修复**：

- 依赖审计发现早期选择的 Vite 6.4.1 存在高等级开发服务器漏洞 → 升级并锁定 6.4.6，官方 npm registry 审计为 0 项漏洞。
- 初版退出连接时可能清除超时但留下未完成 Promise → 统一取消路径和有期限的连接 Promise，取消后释放 Peer/Relay 与定时器。

**验证结果**：`npm run build` 成功；真实浏览器标题、进入游戏和商店均可加载，浏览器完整测试无未捕获运行时错误。入口、动态导入的两个联机 SDK 及相对资源路径均参与构建。单机首包不依赖远程图片、字体或音频下载。

## 第 2 轮 · 核心玩法

**检查点**：修炼与打断、基础御剑、怪物 AI、死亡/掉落/拾取、购买、炼器、炼丹、五境推进、失败、重生与数据边界。

**发现的问题 → 修复**：

- 打开面板或收到死亡事件时会在固定更新内重置时钟；原先步后扣减累加器会产生负余量 → 改为先扣除固定步长，再执行回调，加入回归测试。
- 切换不同境界后再次打开突破面板，旧面板内容可能复用 → 每次开启面板重新建立内容，定时 HUD 只更新数值与条件。
- 初始取材测试误把 78% 概率掉落视为每次必掉 → 测试真实连续斩妖/拾取直到条件达成，不修改掉落概率规避测试。
- 世界快照中的冷却数组与突破对象原先仍引用模拟内存 → 拍快照时复制这些可变字段，验证生成后的快照不被未来更新改写。

**验证结果**：

- 真实键盘行走、修炼与移动打断；真实鼠标御剑击杀普通 AI 并产生掉落。
- 拾取、买药、淬炼、炼丹通过实际 UI 验证；位移与高境界准备条件在部分自动化测试中由开发接口构造，结算路径未替换。
- 五境和全部十五技能的伤害/蓝耗/冷却、渡厄丹、概率失败、复活、旅行门槛与古碑一次性奖励均通过模拟测试。
- 连续十分钟、四人 AI 模拟检查未出现 NaN、负气血或实体无界增长。
- 死亡和突破失败页面都有实际浏览器截图，点击即可继续，不刷新页面。

## 第 3 轮 · 视觉与特效

**检查点**：十五神通的独立视觉、前摇/释放/命中/消散、突破全屏演出、战斗反馈、区域氛围、粒子池与低帧率降级。

**发现的问题 → 修复**：

- 首轮环境地表显得平、建筑过于简略 → 添加碎石道路、草叶、细颗粒纹理、屋瓦、垂幡、层次阴影和朱砂枫树，全部缓存到离屏画布。
- 三技能同时释放和太虚归一的亮核过大 → 降低加色强度、缩小实心亮核，换成柔光、细符阵与分层星芒；雷电增加细碎折线和支路。
- 最初自适应只看绘制 CPU 时间 → 同时监测实际 FPS，在帧率低于阈值时减少粒子。

**验证结果**：

- 已分别捕获十五个技能的效果图，以及三区域、突破成功与失败的截图并查看代表性画面。
- 粒子压力注入最多保留 1700 个对象；生命周期结束后活动数为 0，再发射复用 60 个对象成功。
- 人为降低 FPS 采样触发画质降级，游戏伤害与逻辑不改变。
- 特效包括剑刃、莲瓣、风弧、火羽、冰晶、分叉雷电、金轮、涡旋、陨星、分身剑影、星图、灵绫、星河、龙形轨迹与天门光柱；具有色彩与几何差异。

## 第 4 轮 · 联机与异常

**检查点**：创建、房间号加入、URL 自动加入、四人容量、状态/技能同步、聊天、无效编号、重复加入、断线重连、房主离开、后台状态和高延迟。

**发现的问题 → 修复**：

- 曾当过房主的客户端保留房主 Peer ID，再作为客机加入会不符合握手身份格式 → 切换角色时生成合法客机身份。
- 房主后台时新加入的客机不知道暂停状态 → 初始欢迎快照显式带暂停标志，加入即等待房主。
- 原生 GameRelay 房间号可能短于默认六位 → 解析接受该服务的实际格式；默认 PeerJS 仍生成六位。
- 加强对恶意/损坏数值、重复动作序号、消息大小、快照数组、实体类型和非有限坐标的检查，拒绝无效状态。

**验证结果**：

- 四个独立浏览器上下文，经真实 PeerJS 公共信令和真实 WebRTC 数据通道连接；不是 BroadcastChannel 假联机。
- 移动同步样本中房主与客机都为 `x=1257.6666666666633`；技能冷却与种子一致。
- 第五人收到满房提示，重复身份被拒绝；聊天中的 `<script>` 作为文本显示。
- 主动关闭实际 RTC 数据通道后，客机自动重连并恢复四人队伍。
- 房主离开，三位客机都保留修为转为可玩单机；不存在的房间明确报错。
- 注入输入 160ms + 快照 160ms 的延迟后，移动收敛到房主，技能仍结算。
- 取消连接、旧房主加入新房间、客机暂离、房主暂停时加入、离线创建失败后单机恢复、缺少 GameRelay key 的错误路径均通过。

**验证边界**：真实联网测试的浏览器会话在同一台机器/网络中，未覆盖所有公网 NAT 组合；GameRelay 专属 key 未提供，因此不把其真实服务端完整对局标为通过。

## 第 5 轮 · 高刷新率、2K、输入、存档与部署

**检查点**：60/144/165Hz 时间一致、rAF 无锁帧、2K/DPR、窗口缩放、快速多按键、后台暂停、持久化、损坏存档、构建路径和静态发布。

**发现的问题 → 修复**：

- 初版损坏存档测试在刷新前写入坏数据，被正确的卸载存档逻辑覆盖 → 改在页面初始化时注入损坏数据，确保真正验证读档异常恢复。
- 网络和截图测试最初固定 Edge 启动参数 → 按操作系统选择 Edge 或已安装的 Chromium，README 给出安装方式。

**验证结果**：

| 项目                       | 实测                                           |
| -------------------------- | ---------------------------------------------- |
| 60 / 144 / 165Hz，持续五秒 | 均为 300 个模拟 tick；距离、冷却、灵息完全相同 |
| 默认浏览器窗口             | 观测约 165 FPS，无人工 60 帧渲染上限           |
| 2560×1440，DPR1            | backing store 2560×1440；该轮采样约 150 FPS    |
| 2560×1440，DPR2            | backing store 5120×2880；该轮采样约 131 FPS    |
| 快速三个技能输入           | 三个均执行并获得确认，无重复扣费               |
| 模拟隐藏/恢复事件          | 隐藏期间 tick 不增，恢复无后台追赶             |
| 刷新页面                   | 境界、灵石、淬炼等级恢复一致                   |
| 损坏 JSON                  | 提示异常并启动可玩新旅程，无白屏               |
| 窄屏 390×844               | 无横向溢出，技能与菜单可见                     |

帧率为这台设备、这些测试窗口的采样，不是跨设备性能承诺。目标是支持 165Hz，不锁渲染速率；模拟速度独立于显示刷新率。

自动化脚本包含 `15` 个模拟用例，以及浏览器场景、`12` 个主联机项目和 `8` 个联机边界项目。原始结果和截图由脚本写入 `artifacts/`。GitHub Actions 同样运行模拟测试后才构建部署。

## 已知限制与结论

已检查路径中未发现仍未修复、可复现的阻断性问题；不宣称绝对零 Bug。明确保留的限制是公共信令/NAT 可达性、未配置的 GameRelay 实服验证、房主离开关闭房间、本地存档无防作弊、高延迟位置校正，以及桌面优先的三张 2D 场景。原因和规避方式完整列在 [README](../README.md#已知限制)。
